# Прогресс разработки

Последнее обновление: 2026-10-22.

## Цель

Веб-приложение: фото страницы тетради с телефона → распознавание рукописного литовского текста → правка → документ Word. Распознавание локальное (без облака и токенов) и со временем подстраивается под почерк пользователя.

## Принятые решения

- **Платформа:** веб-приложение (FastAPI + одна HTML-страница). Сервер работает на компьютере, телефон открывает его по Wi-Fi.
- **Основной компьютер:** Windows с NVIDIA RTX 3060 12 ГБ. На Mac (M3, 8 ГБ) тот же код работает с маленькой моделью.
- **Без облачных API:** пользователь не хочет тратить токены. Ранняя версия с Claude API заменена локальной моделью.
- **Модель:** `Qwen/Qwen3-VL-8B-Instruct` в 4-битном режиме (bitsandbytes) на CUDA, около 6 ГБ видеопамяти. На Mac и CPU используется `Qwen/Qwen3-VL-2B-Instruct`. Переопределяется через `HANDAPP_MODEL`.
- **Персонализация, три уровня:**
  1. словарь исправлений (слово, исправленное одинаково ≥2 раз, правится автоматически и подсвечивается);
  2. подсказки из словаря в промпте;
  3. дообучение LoRA (`app/train.py`) на проверенных страницах и образцах.
- **Проверка по смыслу (2026-10-22):** вторая модель `unsloth/gemma-3-12b-it-bnb-4bit` (уже 4-битная, без входа в Hugging Face) правит слова по контексту, плюс словарь Hunspell lt_LT. Пользователь выбрал Gemma за хороший литовский. Модели по очереди делят видеокарту (обе вместе не влезают в 12 ГБ). Запасной вариант, если ошибок много: Qwen3-VL-30B-A3B через llama.cpp с выгрузкой в ОЗУ (у пользователя 32 ГБ).
- **Синтетические строки (2026-10-22):** открытого набора современного литовского почерка не нашлось (картотека LKŽ на clarin-repo.lt без проверенных подписей и не открывается у пользователя). Вместо этого строки рисуются рукописными шрифтами.

## Что сделано

- `app/main.py`: API для страниц, образцов, статистики, экспорта .docx и датасета (zip). Модель загружается в фоне при старте; при старте печатается адрес для телефона.
- `app/local_model.py`: загрузка модели (4-бит на CUDA, fp16 на MPS), подключение LoRA-адаптера из `data/adapter`, генерация. Ограничение размера фото задаётся через `HANDAPP_MAX_PIXELS`.
- `app/ocr.py`: промпт `BASE_PROMPT` (он же используется при обучении), подсказки из словаря, автозамена, пометки `{{слово}}` для неуверенных слов. `HANDAPP_OCR=mock` включает тестовый режим.
- `app/learning.py`: извлекает исправления слов и букв из правок пользователя (difflib, с выравниванием по похожести в неровных блоках).
- `app/train.py`: QLoRA только на языковой части модели, лёгкая аугментация, CER на отложенных страницах до и после. Адаптер сохраняется, только если стало лучше; прошлый лежит в `data/adapter_prev`.
- `app/docx_export.py`: подмножество Markdown (заголовки, списки, жирный, подчёркнутый, зачёркнутый) → .docx, язык lt-LT.
- `app/static/index.html`: мобильный интерфейс: камера/галерея, правка рядом с фото, панель литовских букв, порядок страниц, архив, образцы почерка, статистика обучения.
- `app/segment.py` (2026-10-22): нарезка фото строки на буквы или слова. Без модели, только PIL и numpy: выравнивание освещения, порог Otsu среди тёмных пикселей (отделяет ручку от бледной клетки/линовки), удаление длинных прямых линий, затем проекции: строки по горизонтали, кусочки по вертикали. Точки и хвостики (ė, į, š, ž, ą) стоят над/под буквой, поэтому остаются с ней. Число кусочков подгоняется под подпись: лишние объединяются по самым узким промежуткам, слипшиеся буквы режутся в месте с наименьшим количеством чернил. Несколько строк на фото тоже работают (конец строки всегда граница).
- Вкладка «Мой почерк» → «Нарезать строку на буквы»: подпись, режим «по буквам»/«по словам», фото. Показывается фото с рамками и кусочки с подписями; подпись можно исправить, неудачный кусочек выключить нажатием. «Сохранить» кладёт каждый кусочек как отдельный образец (поле `line` = id строки) и по желанию всю строку целиком. API: `POST /api/samples/line` (предпросмотр, фото строки хранится в `data/samples/lines/`, неподтверждённые удаляются через сутки), `POST /api/samples/line/{id}` (сохранение). Кусочки попадают в `train.py` как обычные образцы.
- Windows: `setup.bat` (venv + PyTorch cu128 + зависимости), `run.bat`, `train.bat`. Mac: `run.sh`.
- `start.bat` (2026-10-22): один ярлык на всё. Обновляет код через `git fetch` + `git merge --ff-only` (никогда не сливает и не стирает; `data\` игнорируется git), ставит библиотеки через `setup.bat auto` только если нет `.venv` или изменился `requirements.txt` (SHA256 хранится в `.venv\requirements.sha`), затем вызывает `run.bat`. Нет интернета или обновление конфликтует с локальными изменениями: понятное сообщение, 20 секунд паузы, запуск текущей версии. Сам себя запускает из копии в `%TEMP%`, потому что `git pull` может заменить работающий .bat. `setup.bat` теперь останавливается при ошибке pip и принимает `auto` (без паузы в конце).
- `README.md`: инструкция для пользователя.
- `allow_phone.bat`: правило брандмауэра для порта 8000 (у пользователя телефон сначала не подключался). При старте сервер печатает все свои IPv4-адреса.

## Что проверено (на Mac)

- Весь API и интерфейс в тестовом режиме (`HANDAPP_OCR=mock`), включая мобильную ширину экрана: загрузка, правка, панель букв, учёт исправлений, автозамена, экспорт .docx, датасет.
- Реальный код загрузки модели, распознавания и дообучения на крошечной Qwen3-VL со случайными весами (настоящие файлы токенизатора и конфигурации): генерация работает, маскирование меток верное (в loss идёт только ответ), обучение делает шаги, адаптер сохраняется и подхватывается при распознавании.

- `app/spell.py` (2026-10-22): литовский словарь Hunspell (LibreOffice lt_LT через `spylls`, чистый Python), скачивается в `data/dict/`. Слова с проверенных страниц и из исправлений считаются известными. Сокращения (LR, KTU-ą), числа и формулы не проверяются. Результат в поле страницы `unknown`.
- `app/context_fix.py` (2026-10-22): фоновая проверка по смыслу. После распознавания `fix_status = "pending"`; поток-корректор ждёт `HANDAPP_FIX_IDLE` секунд тишины у распознавателя, затем проверяет все ожидающие страницы, уступая видеокарту новым фото. В промпт идут сомнительные слова, слова не из словаря с подсказками Hunspell и частые исправления пользователя. `merge()` принимает только замены слово-в-слово, похожие по написанию (без учёта диакритики, сходство ≥ 0.6, без цифр), и только если новое слово есть в словаре; если меняется больше 30% слов, вариант отбрасывается. Текст сохраняет исходную разметку. Если пользователь уже сохранил страницу, `fix_status = "skipped"`. Поля страницы: `ocr_text` (как прочитал Qwen), `text`, `changes` [{from, to}], `unknown`, `fix_status`, `fix_error`. В тестовом режиме вместо Gemma берётся первая подсказка словаря.
- `app/gpu.py` (2026-10-22): общий замок видеокарты; `gpu.use(name)` выгружает другую модель (если не `HANDAPP_KEEP_BOTH=1`), считает ожидающих и время последнего использования.
- Интерфейс: голубые метки «было → стало», пунктирные «нет в словаре», метка «проверяю по смыслу…», опрос `/api/pages` каждые 4 с, пока есть ожидающие страницы (не перерисовывает, пока фокус в поле текста, и не затирает набранный текст). На вкладке «Обучение» видно модель-корректор, словарь и число синтетических строк.
- `app/synth.py` + `synth.bat` (2026-10-22): синтетические строки. 23 шрифта Google Fonts (OFL) с полным набором литовских букв, включая школьную пропись Playwrite PL/CZ/HU; при скачивании покрытие проверяется через fontTools. Текст: случайные статьи lt.wikipedia (кэш `data/texts/wikipedia.txt`), любые .txt в `data/texts/`, проверенные страницы. Рисование: слова с разбросом размера, высоты и наклона, общий наклон, «дрожание» штрихов, бумага в клетку/линейку/чистая, синие и чёрные чернила, неровный свет, шум, размытие, JPEG. Около 0.07 с на строку. Результат: `data/synthetic/*.jpg` и `lines.json`.
- `train.py`: каждую эпоху подмешивает новую случайную порцию синтетических строк (`--synth N`, по умолчанию вдвое больше своих примеров, но не более 1500). Точность по-прежнему меряется только на настоящих страницах.

## Команды проверки

Тестовый режим без модели (Mac или Windows):

```bash
HANDAPP_OCR=mock HANDAPP_DATA=/tmp/handapp-test .venv/bin/uvicorn app.main:app --port 8765
```

Запуск с моделью:

```bash
./run.sh
```

На Windows: `start.bat` (обновление, установка при необходимости и запуск). По отдельности: `setup.bat` один раз, затем `run.bat`.

Дообучение (сервер должен быть остановлен):

```bash
.venv/bin/python -m app.train --epochs 3
```

На Windows: `train.bat`. Быстрый прогон для проверки кода: `--max-steps 2 --no-eval`.

Проверка нарезки строки (выводит число кусочков и предупреждения):

```bash
.venv/bin/python -c "from PIL import Image; from app import segment as s; print(s.segment(Image.open('строка.jpg'), len(s.labels_for('a ą b c', 'letters'))))"
```

Синтетические строки (небольшая проба):

```bash
.venv/bin/python -m app.synth --count 50 --wiki 20
```

Проверка извлечения исправлений:

```bash
.venv/bin/python -c "from app.learning import correction_pairs as c; print(c('as nuejau i mokykla','aš nuėjau į mokyklą'))"
```
